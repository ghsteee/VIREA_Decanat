# Деплой на российский VPS

Задача 3.2. Всё приложение — четыре контейнера из `docker-compose.yml`: PostgreSQL 16, приложение Next.js, разовые команды (`tools`) и Caddy с HTTPS.

## Что нужно заранее

- VPS в России с Ubuntu 22.04/24.04, 2 ГБ памяти, 20 ГБ диска (выбирает Алёна, см. `docs/status.md`).
- Домен с A-записью на адрес VPS — Caddy сам получит сертификат Let's Encrypt.
- Открытые порты 80 и 443.

## Быстрый путь: скрипт

[`deploy/setup-server.sh`](../../deploy/setup-server.sh) делает всё из раздела «Первый запуск»: ставит Docker из репозитория Ubuntu, включает файрвол (22, 80, 443), при нехватке памяти — подкачку, проверяет Docker Hub, создаёт ключ для чтения приватного репозитория, клонирует проект в `/opt/dekanych`, создаёт `.env` со случайными секретами, собирает и запускает контейнеры, применяет миграции и загружает демо.

```bash
sudo bash setup-server.sh <домен>
```

Первый запуск остановится и покажет публичный ключ — его нужно добавить в GitHub (Settings → Deploy keys, только чтение) и запустить скрипт ещё раз. Пароль тестовых аккаунтов скрипт печатает один раз — сохранить в менеджер паролей.

## Первый запуск вручную

1. Установить Docker Engine и плагин Compose по официальной инструкции Docker для Ubuntu.
2. Проверить, что образы скачиваются: `docker pull node:22-bookworm-slim`. Если Docker Hub с сервера недоступен — **нужно уточнить** зеркало реестра у хостинга (многие российские хостинги дают своё) и прописать его в `/etc/docker/daemon.json` (`registry-mirrors`).
3. Склонировать репозиторий и создать `.env` по образцу `.env.example`:
   - `DOMAIN` — домен сайта;
   - `POSTGRES_PASSWORD` — `openssl rand -hex 24`;
   - `SESSION_SECRET` — `openssl rand -hex 32`;
   - `SEED_PASSWORD` — пароль тестовых аккаунтов для жюри; в репозиторий, журнал и PR не попадает;
   - ключи почты, push и GigaChat — по мере готовности задач этапа 4.
4. Положить сертификаты НУЦ Минцифры в `deploy/certs/russian_trusted_ca.pem` (для GigaChat) — по [`deploy/certs/README.md`](../../deploy/certs/README.md).
5. Собрать и запустить:

```bash
docker compose up -d --build
```

6. Применить миграции и загрузить демо:

```bash
docker compose run --rm tools npx prisma migrate deploy
```

```bash
docker compose run --rm tools npm run db:seed
```

7. Открыть `https://<домен>/login` с телефона без VPN.

## Push-уведомления (VAPID)

Новый сервер получает ключи VAPID автоматически (`deploy/setup-server.sh` вызывает `deploy/gen-vapid.sh`). На уже настроенном сервере — один раз:

```bash
cd /opt/dekanych && sudo bash deploy/gen-vapid.sh .env && sudo docker compose up -d
```

Ключи — только в `.env`. Если их поменять, старые подписки браузеров перестанут работать — студентам придётся включить push заново.

## Обновление

```bash
git pull && docker compose up -d --build && docker compose run --rm tools npx prisma migrate deploy
```

## Утренний сброс демо

События «сегодня» в демо строятся от текущей даты. Чтобы перед показом жюри всё было свежим, сид можно запускать каждое утро по cron (в 05:00 МСК):

```
0 5 * * * cd /opt/dekanych && docker compose run --rm tools npm run db:seed >> /var/log/dekanych-seed.log 2>&1
```

## Грабли первого деплоя

- **Yandex Cloud:** у нового облака квота SSD — 10 ГБ, HDD — 20 ГБ на зону; взяли HDD 20 ГБ, этого хватает. Вход по SSH — под логином, указанным при создании ВМ, не `root`.
- **REG.RU:** если вместе с доменом куплен хостинг, домену назначаются DNS-серверы хостинга (`ns*.hosting.reg.ru`) со своей зоной. A-записи нужно править в той зоне, которую реально отдают DNS-серверы домена (видно по `whois dekanych.ru | grep nserver`).
- **Заглушка REG.RU:** в зоне хостинга есть A `37.140.192.242` и AAAA `2a00:f940:…` для `@` и `www`. Их нужно удалить: иначе часть посетителей попадает на заглушку, а Let's Encrypt проверяет домен по IPv6 и не выдаёт сертификат.
- **Google DNS с ВМ Yandex Cloud** может не отвечать — проверять через `nslookup dekanych.ru 77.88.8.8`.
- 12.11: после чистки зоны и `docker compose restart caddy` сертификат получен, сайт открывается на https://dekanych.ru.
- **Угловые скобки** в инструкциях (`<домен>`) — место для подстановки, в терминале их не набирать.

## Безопасность

- `.env` только на сервере, права `600`.
- Caddy не доверяет чужому `X-Forwarded-For` и подставляет адрес клиента — на этом держится лимит попыток входа.
- Порт базы наружу не открыт: PostgreSQL доступен только контейнерам.
- `restart: unless-stopped` — автоперезапуск после сбоя и перезагрузки сервера (NF7).
