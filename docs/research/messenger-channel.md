# Проверка канала мессенджера

9 ноября 2026 года. Этап 2a. Требования [N2, N3 и S2/S8](../PRD.md).

## MAX

Обычный аккаунт физлица не может пройти верификацию на платформе MAX для партнёров. Для создания бота нужен верифицированный профиль российского юрлица, ИП или самозанятого. Официальный процесс проходит через платформу или мини-приложение «MAX для бизнеса» и включает модерацию бота. Путь через `@MasterBot` для обычного аккаунта в актуальной инструкции не указан. [Верификация](https://dev.max.ru/docs/maxbusiness/connection), [создание и модерация](https://dev.max.ru/docs/chatbots/bots-create/create).

После модерации сервер отправляет сообщения через `POST /messages` с токеном в заголовке `Authorization`. Документация указывает хост `platform-api2.max.ru` и доверенный сертификат Минцифры. Это требования API. Авторизованный запрос из нашего окружения и доставка в MAX не проверялись. [Отправка сообщений MAX](https://dev.max.ru/docs-api/methods/POST/messages).

## Резервный вариант ВКонтакте

В [принятых решениях](../context.md) уже предусмотрен бот сообщества ВКонтакте, если обычного аккаунта для MAX недостаточно. Web push остаётся основным каналом. Официальная схема VK подтверждает, что ключ сообщества подходит для `messages.send`, а личный диалог задаётся `peer_id`. Для повторов одной операции сохраняем один `random_id`. Входящие сообщения можно получить через Bots Long Poll. [Схема messages.send](https://raw.githubusercontent.com/VKCOM/vk-api-schema/master/messages/methods.json#L2245), [схема groups.getLongPollServer](https://raw.githubusercontent.com/VKCOM/vk-api-schema/master/groups/methods.json#L1508), [примеры SDK ВКонтакте](https://github.com/VKCOM/java-sdk-examples).

## Прогон с российского VPS без VPN

Нужны доступ администратора к тестовому сообществу, тестовый получатель под контролем команды и российский VPS. Действующие ключи передаются серверу через окружение. В журнал пишем этап, результат и время, без токенов, реальных идентификаторов и сырых событий.

1. Включить сообщения сообщества и Long Poll для `message_new`. Создать ключ сообщества с доступом к сообщениям.
2. Открыть личный диалог с сообществом из тестового аккаунта. Отправить одноразовый код, выданный кабинетом на 10 минут. На сервере сверить сообщество и тип диалога, погасить код и сохранить назначение из входящего события. Повторный, просроченный код и код из группового чата должны отклоняться.
3. С VPS вызвать `messages.send` с ключом сообщества, `peer_id` привязанного диалога, `random_id` тестового события и вымышленным сообщением со ссылкой на кабинет. Проверить ответ API и фактическое получение на телефоне без VPN.
4. На прототипе повторить S2 с переносом пары. От момента публикации до получения push и сообщения должно пройти не более 60 секунд. Контрольный аккаунт из другой группы ничего не получает. После отвязки повторное событие в этот диалог не отправляется.

Проверка документации завершена. Сквозной прогон ещё предстоит, тестового сообщества и российского VPS в текущем окружении нет.
