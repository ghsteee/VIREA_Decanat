# PRD: цифровой деканат ВТУ ВИРЭА

«Деканыч» — личный кабинет студента ВТУ ВИРЭА, вымышленного вуза по мотивам РТУ МИРЭА (концепт для хакатона). Кабинет сообщает студенту о переносах и дедлайнах через web push и письма на подтверждённую почту. Основа — опрос 20 студентов (`docs/research/survey-summary.md`).

Документ для людей и для ИИ-агентов: у каждого требования есть номер и проверяемый критерий. Номер требования пишем в коммитах и PR.

> Этот файл — основная версия PRD. Копия в Claude Docs больше не обновляется.

## Ключевые сценарии

Девять сценариев — то, что покажем жюри и покроем e2e-тестами. S1–S4 и S9 обязательны к 16 ноября в части Must; части критериев, помеченные *(Should)* или *(Could)*, доделываем по приоритету соответствующего требования.

| ID | Кто | Сценарий | Готово, когда |
| --- | --- | --- | --- |
| S1 | Данила | Утром открывает кабинет: сверху — ближайшая пара с аудиторией и корпусом, под ней — изменения на сегодня | После входа достаточно 0 касаний; на 360×640 ближайшая пара видна без прокрутки, и если она сама изменена — сразу с меткой «было → стало» (R3); этаж — *(Should, R4)* |
| S2 | Ирина → Данила | Сотрудник переносит пару группы; студент получает push и письмо, если оба канала включены | В демо push появляется на устройстве, а письмо — во входящих тестового ящика за ≤ 60 с от публикации. В ленте и расписании видно «было → стало» (время, аудитория, формат). Другие группы ничего не получают |
| S3 | Ирина → Ксения | Сотрудник добавляет дедлайн (пересдача, приём заявлений на стипендию) | Дедлайн в списке и на «Сегодня», если до него ≤ 7 дней; напоминания за 3 дня и за 1 день. Для демо у сотрудника есть кнопка «отправить напоминание сейчас» *(Should, E4)* |
| S4 | Марат ↔ Ирина | Студент заказывает справку об обучении; сотрудник ведёт её по статусам | Данные из профиля; от каталога до отправки ≤ 5 касаний; выбор получения — электронно или слот в окна без пар *(Should, A3)*, PDF с QR *(Could, A5)*; статусы «Подана → В работе → Готова → Выдана» (или «Отклонена» с причиной); каждая смена — уведомление |
| S5 | Ксения | Проверяет, что нужно для допуска по дисциплине | Оценки, чек-лист «3 из 5 лаб сдано, срок 20.12» и статус «допущен / риск / не допущен»; сводка по сессии одной фразой |
| S6 | Марат | Староста публикует изменение или дедлайн для своей группы | Сообщение с пометкой «от старосты», доходит как в S2; староста видит «прочитали N из M»; публикация в чужую группу запрещена на сервере |
| S7 | Ксения | Спрашивает ИИ-помощника «как пересдать экзамен?» и «нужна справка в военкомат» | Ответ со ссылкой на пункт документа; на просьбу о справке — заполненный черновик, отправка только кнопкой студента; на вопрос о чужих данных — отказ |
| S8 | любой студент | Включает доступные каналы уведомлений | Push включается в 2 касания, если канал настроен и браузер поддерживает его (на iPhone — из PWA на экране «Домой»). При настроенной почте студент указывает адрес в профиле и вводит одноразовый код (10 минут); там же меняет адрес или отключает письма. Ненастроенные и неподдерживаемые каналы скрыты по просьбе пользователя 21.11 |
| S9 | Данила vs Ксения | Студент подставляет в адрес id чужой заявки или профиля | Ответ 404; данные не утекают ни в HTML, ни в API; студент не открывает `/staff` |

## Разделы и требования

Приоритеты: **Must** — без этого не сдаём (к 16 ноября), **Should** — фишки 17–19 ноября, **Could** — если останется время.

| ID | Раздел | Требование | Приоритет |
| --- | --- | --- | --- |
| T1 | Сегодня | Блоки строго по порядку: ближайшая пара → изменения на сегодня и завтра (блок скрыт, если изменений нет) → дедлайны на 7 дней → новые оценки → активные заявки | Must |
| T2 | Сегодня | Пустые состояния: «Сегодня пар нет», «Всё по расписанию», «Дедлайнов на неделе нет» | Must |
| R1 | Расписание | День и неделя, номер учебной недели, переход между днями свайпом и кнопками | Must |
| R2 | Расписание | Карточка пары: время, дисциплина, тип (лекция, практика, лаба), преподаватель, аудитория, корпус, формат; для онлайн-пары — ссылка | Must |
| R3 | Расписание | Изменения видны как «было → стало» с меткой «Перенесена / Отменена / Дистант / Другая аудитория» | Must |
| R4 | Расписание | «Где аудитория»: корпус, адрес, этаж, ссылка на карту | Should |
| R5 | Расписание | Данные из парсера открытого расписания МИРЭА; ФИО преподавателей заменены вымышленными | Must |
| N1 | Уведомления | Лента: изменения, дедлайны, объявления, статусы заявок; фильтры по типу, важность, счётчик непрочитанного, отметка «прочитано» | Must |
| N2 | Уведомления | Письма на подтверждённую почту. Срочные изменения, новые срочные дедлайны и напоминания D2 отправляются сразу. В письме краткое сообщение и ссылка в кабинет. Цель доставки при переносе пары — ≤ 60 с во входящие тестового ящика. Адрес студент указывает сам: корпоративную почту, по опросу, не читают | Must |
| N3 | Уведомления | Web push через PWA показывается только при настроенном канале и поддержке браузером. На iPhone — в PWA после добавления на экран «Домой». Недоступный переключатель и подсказки скрыты по просьбе пользователя 21.11 | Must |
| N4 | Уведомления | Настройки: какие типы в какой канал отправлять | Could |
| N5 | Уведомления | Утренний дайджест несрочных уведомлений на подтверждённую почту. Срочные письма и напоминания D2 приходят отдельно по N2 | Should |
| D1 | Дедлайны | Список по дате: что, когда, дисциплина, кто опубликовал (дирекция / преподаватель / староста); просроченные отдельно | Must |
| D2 | Дедлайны | Напоминания за 3 дня и за 1 день во все каналы | Must |
| D3 | Дедлайны | Студент отмечает «сделано» — напоминания прекращаются | Should |
| G1 | Успеваемость | Оценки по дисциплинам текущего семестра, зачёты и экзамены сессии, история прошлых семестров | Must |
| G2 | Успеваемость | Сводка «как дела» одной фразой: средний балл, долги, статус допуска к сессии | Must |
| G3 | Успеваемость | Чек-лист допуска по дисциплине: требования, прогресс, сроки; статус «допущен / риск / не допущен» | Should |
| A1 | Заявки | Каталог: справка об обучении, для военкомата, о стипендии; заявления на пересдачу, повышенную стипендию, матпомощь | Must |
| A2 | Заявки | Автозаполнение из профиля; студент вводит только то, чего в профиле нет (куда, количество) | Must |
| A3 | Заявки | Способ получения: электронно или слот выдачи; предлагаем только окна без пар студента | Should |
| A4 | Заявки | Статусы с историей и временем; при отказе — причина и кнопка «подать заново» | Must |
| A5 | Заявки | Готовая справка — PDF с QR-кодом проверки подлинности | Could |
| P1 | Профиль | ФИО, институт, направление, курс, группа, форма обучения, номер студенческого (вымышленные) | Must |
| P2 | Профиль | Электронный студенческий с QR (подписанная ссылка, срок жизни 5 минут) | Should |
| P3 | Профиль | Включение push, добавление и подтверждение почты, смена адреса и отключение писем, светлая и тёмная темы, выход | Must |
| E1 | Сотрудник | Очередь заявок с фильтрами по типу и статусу, смена статуса, причина отказа | Must |
| E2 | Сотрудник | Перенос, отмена, смена аудитории или формата пары для группы или потока | Must |
| E3 | Сотрудник | Дедлайны и объявления для выбранных групп, курса или института | Must |
| E4 | Сотрудник | Демо-кнопка «отправить напоминание сейчас», чтобы показать D2 без ожидания | Should |
| H1 | Староста | Публикация изменения, дедлайна или объявления для своей группы; счётчик «прочитали N из M» | Should |
| AI1 | ИИ-помощник | Чат с ответами по базе документов; каждый ответ со ссылкой на пункт; если ответа нет — так и говорит и предлагает написать в дирекцию | Should |
| AI2 | ИИ-помощник | Черновик заявки из диалога; отправка только после подтверждения студента | Should |

| X1 | Общее | Вуз в интерфейсе везде называется ВТУ ВИРЭА. Короткая метка «Учебный прототип» на входе и в шапке кабинета; длинное пояснение и подвал убраны по просьбе пользователя 21.11. Сервис называется «Деканыч», свой логотип (`docs/brand/`), вымышленные данные | Must |

Навигация на телефоне — нижнее меню из 5 пунктов: Сегодня · Расписание · Учёба (успеваемость + дедлайны) · Заявки · Профиль. Уведомления — колокольчик в шапке, помощник — плавающая кнопка. На компьютере то же самое в боковой панели.

## Роли и права

Три роли; староста — это студент с дополнительным правом на свою группу. Все проверки на сервере, `userId` и роль берутся только из сессии.

| Действие | Студент | Староста | Сотрудник дирекции |
| --- | --- | --- | --- |
| Видеть свой профиль, оценки, заявки | да | да | — |
| Видеть расписание и дедлайны своей группы | да | да | всех групп своего института |
| Подавать заявки, спрашивать ИИ-помощника | да | да | — |
| Публиковать изменения, дедлайны, объявления | — | только для своей группы, с пометкой «от старосты» | для групп, курса, института |
| Видеть и обрабатывать заявки студентов | — | — | да, все действия пишутся в журнал |
| Видеть оценки других студентов | — | — | — (в прототипе не нужно) |

Староста не видит оценки и заявки одногруппников — только счётчик «прочитали N из M» без имён.

## Вне рамок и открытые вопросы

Не делаем в прототипе:

- Экспорт расписания в календарь и полноценный офлайн — по опросу не нужны.
- Задания и материалы курсов — это зона СДО, дублировать не будем.
- Кабинет преподавателя и выставление оценок: оценки — сиды.
- Реальная интеграция с системами МИРЭА и настоящий вход — запрещены условиями хакатона. Исключение — открытое расписание.
- Оплата, общежитие, чат с преподавателями.
