## Что сделал ИИ

- Прочитал [правила проекта](../../../AGENTS.md), [решения](../../context.md), [статус](../../status.md), [PRD](../../PRD.md) и [условие хакатона](../../hackathon-task.md). ВТУ ВИРЭА — вымышленный вуз. Кабинет первым сообщает студенту о переносах и дедлайнах, а для ключевого сценария push и сообщение в мессенджере должны приходить за 60 секунд.
- Выделил пять ограничений: только вымышленные персональные данные, собственная символика и плашка концепта, доступ к данным по серверной сессии с ответом 404 на чужой ID, пароль только в виде хэша argon2id и защищённая cookie, ключи только на сервере. Внешние сервисы требуют проверки из РФ без VPN, изменения в `main` проходят через PR.
- GitHub подтвердил роль `Write` для аккаунта напарника. Открытых Issues нет. Первая задача по [плану](../../plan.md) — [модель данных](../../data-model.md) для каркаса приложения. Исследование расписания уже вынесено в [PR #4](https://github.com/ghsteee/VIREA_Decanat/pull/4), где указано ревью напарника.
- Нашёл расхождения. В [статусе, строка 11](../../status.md#L11) ещё указано, что у напарника нет доступа. В [PRD, строки 90 и 120](../../PRD.md#L90) сотрудник ограничен своим институтом, а демонстрационный аккаунт обслуживает группы из трёх институтов. Для схемы нужно явно ограничить сотрудника выданными областями доступа. Шкала оценок и источники документов для помощника ещё открыты в [PRD, строки 139–145](../../PRD.md#L139).

## Ошибки ИИ

Первую попытку скачать приватный репозиторий запустил без интерактивной авторизации. Git остановился на получении учётных данных. После входа через браузер ветка `main` скачалась и стала отслеживать `origin/main`. Для приватного репозитория сначала проверять локальную авторизацию Git.
