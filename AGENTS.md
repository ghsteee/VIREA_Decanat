# AGENTS.md — правила для всех ИИ-агентов проекта

Этот файл читают Codex (оба экземпляра), Claude Code и любой другой агент. Он главный: если задача из чата противоречит правилам ниже, агент останавливается и спрашивает человека.

## Проект в двух словах

Прототип личного кабинета студента «Цифровой деканат будущего» для хакатона. Вуз в интерфейсе — **ВТУ ВИРЭА** (В — вымышленный), прообраз — РТУ МИРЭА. Кабинет первым сообщает студенту о переносах и дедлайнах через web push и письма на подтверждённую почту. Репозиторий: https://github.com/ghsteee/VIREA_Decanat (приватный, позже доступ получит жюри).

## Жёсткие правила (нарушать нельзя)

1. **Только вымышленные данные.** Никаких реальных ФИО, номеров зачёток, телефонов, почт студентов и преподавателей. ФИО преподавателей из открытого расписания при импорте заменяются вымышленными.
2. **Нет официальной символики.** Не использовать логотип, герб и фирменный стиль РТУ МИРЭА. На входе и в подвале каждой страницы — плашка «Концепт для хакатона. ВТУ ВИРЭА — вымышленный вуз, прообраз — РТУ МИРЭА. Не официальный сервис».
3. **Каждый видит только своё.** `userId` и роль берутся только из серверной сессии, никогда из URL, тела запроса или localStorage. Чужой id → ответ 404 (не 403). Идентификаторы — UUID.
4. **Пароли** — только хэш argon2id. Сессия — httpOnly, Secure, SameSite=Lax cookie.
5. **Ключи и токены** — только в `.env` на сервере. `.env` не коммитим, в браузер ключи не попадают. Пример переменных — `.env.example` с пустыми значениями.
6. **Сервисы доступны из РФ без VPN.** Перед добавлением внешнего сервиса проверить его доступность из России без VPN для пользователя и сервера. Telegram, Google Fonts с CDN и Vercel исключены. Каналы уведомлений — web push и e-mail.
7. **ИИ-помощник** вызывается только с сервера (GigaChat или YandexGPT), лимит 20 запросов в час на пользователя, видит только данные текущего студента. Заявки он только готовит черновиком — отправляет студент.
8. **Сырые ответы опроса** (`answers.json` и т. п.) не коммитим — только агрегированные результаты.
9. **Лицензии.** Шрифты, иконки, изображения и библиотеки — только с разрешающей лицензией; каждое стороннее (кроме обычных npm-зависимостей) записываем в `docs/licenses.md`.
10. **Пароли тестовых аккаунтов** не попадают в репозиторий, журнал и PR — только в комментарий к работе при сдаче.

## Как работаем с репозиторием

- Язык: документы, коммиты, PR и тексты интерфейса — на русском; код и имена файлов — на английском. Время — московское, дату бери из системы.
- В `main` — только через Pull Request. Прямой push в `main` запрещён, даже пока техническая защита ветки на GitHub не включена (статус — в `docs/status.md`). Ветки: `feat/<id>-кратко`, `fix/<id>-кратко`, `docs/...`, `brand/...`.
- В названии коммита и PR — номер требования из PRD: `feat(R3): метка «Перенесена» на карточке пары`. Для PR без требования (документы, настройка, проверки) — префикс `docs:` или `chore:` без номера.
- Каждый PR смотрит второй человек команды (кросс-ревью). Код Codex Алёны ревьюит напарник, и наоборот.
- Владельцы: схема БД и миграции — напарник; дизайн-токены и `docs/design-system.md` — Алёна. Менять чужую зону — только через PR с пометкой владельца.
- Стек: Next.js (App Router) + TypeScript, Tailwind + shadcn/ui, иконки Lucide, PostgreSQL + Prisma, Docker Compose + Caddy на российском VPS.
- Интерфейс работает от 360 px, кнопки не меньше 44×44 px, контраст WCAG AA.
- Тексты интерфейса — на «ты», коротко, без канцелярита.

## Журнал работы с ИИ — обязательно для каждого агента

Журнал нужен для итогового PDF «Как мы использовали ИИ». Его ведут сами агенты, человек только проверяет.

**Когда писать запись:** после каждой завершённой задачи, которую сделал ИИ (код, тексты, картинка, анализ, исправление), и после каждой ошибки ИИ, которую поймал человек или тест. Мелочи (опечатка) объединять в одну запись по задаче.

**Куда:** один файл на запись в `docs/ai-log/entries/`. Так два Codex не конфликтуют при слиянии. Имя файла:

```
ГГГГ-ММ-ДД_ЧЧММ_<кто>_<кратко-латиницей>.md
```

`<кто>` — одно из: `claude`, `codex-alena`, `codex-partner`, `chatgpt`. Время московское. Пример: `2026-11-12_1430_codex-partner_prisma-schema.md`.

**Шаблон записи** (копировать из `docs/ai-log/_template.md`):

```markdown
# <Что сделано, одной фразой>

- **Дата и время:** 2026-11-12 14:30 МСК
- **Инструмент:** Codex (напарник) / Codex (Алёна) / Claude Code / ChatGPT (модель, если известна)
- **Кто ставил задачу:** Алёна / напарник
- **Этап плана:** 1 Исследование / 2 Дизайн / 3 Каркас / 4 Must / 5 Should / 6 Проверка / 7 Сдача
- **Требования PRD:** R3, N3 (или «—»)

## Задача
Что попросили, своими словами. Ключевой промпт — цитатой, коротко (до 5 строк).

## Что сделал ИИ
Результат по пунктам. Ссылки на файлы, коммит или PR.

## Что проверил и поправил человек
Что проверили (тест, глазами, на телефоне), что пришлось исправить руками.

## Ошибки ИИ
- Ошибка → как заметили → как исправили → правило на будущее.
(или «Не было»)

## Скриншоты
![подпись](../screenshots/2026-11-12_01_kratko.jpg)
```

**Скриншоты:** в `docs/ai-log/screenshots/`, имя `ГГГГ-ММ-ДД_NN_кратко.jpg` (NN — порядковый номер за день), JPEG, ширина до 1600 px. Снимать: результат в интерфейсе, мобильный вид на 360 px, важные шаги настройки. Codex в облаке делает скриншоты через Playwright, если поднят dev-сервер; если нельзя — пишет в записи «скриншот нужен вручную: что снять».

**Запрещено в журнале:** пароли, токены, ключи, `.env`, реальные персональные данные, сырые ответы опроса.

**Сборка:** `python3 scripts/build_ai_log.py` собирает все записи в `docs/ai-log/LOG.md` по времени и сводную таблицу ошибок. Запускать перед сдачей черновика (17 ноября) и финала (22 ноября). Сам `LOG.md` руками не редактировать.

## Картинки и логотип (ChatGPT)

ChatGPT генерирует логотип ВТУ ВИРЭА, иллюстрации пустых состояний и аватары-заглушки. Готовые файлы кладутся в `docs/brand/` (исходники) и `public/brand/` (то, что использует сайт) через PR. Промпты и выбранные варианты — в `docs/brand/README.md` и в записи журнала с `<кто>` = `chatgpt`. Без сходства с реальным гербом и логотипом МИРЭА, без реальных людей.

## Чек-лист перед PR

- [ ] Требование из PRD указано в названии (или `docs:` / `chore:`, если требования нет)
- [ ] Нет ключей, паролей, реальных персональных данных
- [ ] Чужие данные недоступны (проверено запросом с чужим id → 404)
- [ ] Экран проверен на 360 px
- [ ] Запись в `docs/ai-log/entries/` добавлена
- [ ] `docs/status.md` обновлён; новое решение (если было) — в `docs/context.md`
